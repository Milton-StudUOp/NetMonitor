# Databases

## Default SQLite database

Without an administrative selection or an external `DATABASE_URL`, the backend uses:

```text
backend/network_monitor.db
```

SQLite is suitable for labs, demonstrations, and small installations with a single backend instance.

## Selectable primary database

Connections registered under **Settings → Databases** can be promoted with **Use as Primary**. The selection does not switch the engine during an active request; it is prepared and applied on the next restart.

### Promotion workflow

1. Enable and test the connection.
2. Create the schema at the destination.
3. Refuse promotion if application tables already contain data.
4. Copy data transactionally in dependency order.
5. Restore circular references between devices and links.
6. Compare counts for every table.
7. Store the encrypted selection in `backend/.active-database`.
8. Restart the backend manually.

The file is ignored by Git and contains no plaintext URL. Encryption depends on `SECRET_KEY`.

## Drivers

| Type | SQLAlchemy/Python driver | Notes |
|---|---|---|
| SQLite | `aiosqlite` | Included |
| PostgreSQL | `asyncpg` | Included and recommended for production |
| MySQL/MariaDB | `asyncmy` | Included in premium dependencies |
| SQL Server | `aioodbc` | Requires Microsoft ODBC Driver 18 on the host |
| Oracle | `oracledb` | Thin mode when supported by the server |

## Migration compatibility

The migrator uses dialect-specific adapters:

| Database | Generation after migration | Limited query | Connection test |
|---|---|---|---|
| SQLite | Native ROWID/PK | `LIMIT 100` | Real authentication/open |
| PostgreSQL | `setval(pg_get_serial_sequence(...))` | `LIMIT 100` | Login + `SELECT 1` |
| MySQL | `ALTER TABLE ... AUTO_INCREMENT` | `LIMIT 100` | Login + `SELECT 1` |
| SQL Server | `IDENTITY_INSERT` + `DBCC CHECKIDENT` | `TOP 100` | Login + `SELECT 1` |
| Oracle | Identity/sequence restart or controlled advance | `FETCH FIRST 100 ROWS ONLY` | Login + `SELECT 1 FROM DUAL` |

Numeric keys use `GENERATED BY DEFAULT` when the dialect supports identities. This preserves IDs during copying and allows generation to continue without collisions. JSON fields use native JSON; Oracle stores them as CLOB with transparent serialization.

After changing dependencies:

```powershell
cd backend
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Docker

`docker-compose.yml` defines PostgreSQL as the primary database through `DATABASE_URL`. This variable remains the fallback when no `.active-database` selection exists.

To preserve a selection made in the interface when using containers, mount the backend directory or a volume containing `/app/.active-database`. The development Compose file already mounts `./backend:/app`.

## Data sources

A connection can also supply a SQL data source without becoming the primary database. These sources are explicitly created queries intended for dashboards, correlation, or future monitoring.

Security rules:

- `SELECT` only.
- One statement.
- Separate parameters.
- External limit of 100 rows.
- Read-only permissions for the remote user.

## Recovery

The previous database is retained, and its URL is encrypted as a rollback option. If the promoted database fails during startup, the application lifespan automatically switches to the previous database, updates the activation file, and continues startup. `POST /api/platform/database-runtime/rollback` also prepares a manual return after validating authentication against the previous database.

If the activation file itself is corrupted, move `backend/.active-database` to a safe location and restart. The system will use `DATABASE_URL` or the default SQLite database.

## Real integration tests

The suite always runs DDL tests for all five dialects. Real integrations are enabled through:

```text
NETMONITOR_TEST_POSTGRESQL_URL
NETMONITOR_TEST_MYSQL_URL
NETMONITOR_TEST_MSSQL_URL
NETMONITOR_TEST_ORACLE_URL
```

To allow complete migration tests against exclusively disposable databases:

```text
NETMONITOR_ALLOW_DESTRUCTIVE_DATABASE_TESTS=1
```

This test creates and removes NetMonitor tables in the specified database. Never enable it against a shared or production database. GitHub Actions runs authentication, queries, identity reseeding, and complete migrations against temporary PostgreSQL and MySQL instances. SQL Server and Oracle run when dedicated URLs are provided.

## Production

- Prefer PostgreSQL.
- Use TLS and least-privilege credentials.
- Take native database backups in addition to configuration exports.
- Do not share one SQLite file among multiple instances.
- Keep `SECRET_KEY` outside the image and stable across restarts.
